# Structure Editor · 结构工坊

## 开始编辑

1. 在 **编辑 → 首选项 → 游戏目录** 选择 RimWorld 根目录（含 `Data/Core`）。已识别 Steam 目录时会自动加载。
2. **素材来源** 默认按玩家 `ModsConfig.xml` 自动读取已启用的本地和创意工坊模组；也可以指定其他配置或手动添加额外目录。读取操作不改写玩家的模组启用配置。
3. **文件 → 新建工程**；在右侧“结构”页填写标识和名称。普通结构使用“通用结构”，无需任何模组前缀。
4. 从左侧选取素材，在画布上放置。材质、方向、初始状态的修改直接生效。
5. 右侧 **导出** 页选择 XML 格式及导出目录；默认勾选 **保存时自动导出 XML**。**文件 → 保存** 或 Ctrl+S 会保存 JSON 工程并更新 XML。

结构标识、显示名称和搜索框支持 Ctrl+A/C/X/V/Z 进行文本全选、复制、剪切、粘贴和撤销。将焦点移回画布后，同组快捷键用于布局对象。文本框右键菜单也可复制粘贴。

## 炮塔损毁爆炸范围

画布工具栏的 **损毁爆炸范围** 按钮或 **视图 → 显示炮塔损毁爆炸范围** 可开关显示，默认关闭。橙色圆和半径文字标出所有已放置炮塔的损毁爆炸范围；放置和粘贴预览使用黄色虚线。隐藏建筑图层时同步隐藏范围。

半径读取素材 XML 中的爆炸组件，包含继承的配置；旧游戏同步目录继续使用 XML 半径。范围以炮塔所在格为中心，表示无遮挡时的标称范围，不模拟墙体遮挡、爆炸概率、连锁引爆或模组运行时代码。没有有效爆炸半径的炮塔不显示。开关只影响编辑画布，不写入结构、不产生撤销记录，也不影响 PNG 导出。

## 工作栏与命名

- 顶部工作栏切换结构；“打开”支持多选 JSON/XML，“结构库”可直接调取已有布局。
- 每份文档独立保留修改、撤销和视图。Ctrl+Tab 切换，Ctrl+W 或中键关闭；星号表示未保存。
- 下次启动恢复已打开文件；关闭或退出时逐份询问未保存修改。
- MP 格式的“结构”页选择核心、等级、编号后，自动切换对应结构。优先保留已打开的修改；磁盘同时存在 JSON/XML 时优先 JSON。“复制名称”复制显示名和 DefName。
- 自动查找保存/导出目录、模组结构库、已打开和最近文件的目录，以及桌面和默认工程目录。按文件内容匹配标识，不依赖文件名。
- 没有对应文件时，预填名称并打开空草稿；点击保存才创建结构文件。未修改的空草稿可直接切换，不堆积标签；已修改的草稿保留。
- “下个空号”自动跳过现有结构和打开的草稿。
- 覆盖 XML 前自动备份至 `%LOCALAPPDATA%/StructureEditor/Backups`，同名文档和无关 XML 会拦截。

## 保存与导出

右侧“导出”页提供格式选择、XML 输出文件路径、更改 XML 目录、立即导出、另存为 XML、导出内容包和 PNG 预览。“文件 → 导出”菜单仍可使用。

- 自动导出默认开启，按当前目标格式输出 Framework、原版 PrefabDef 或 MechProtocol XML。
- 新工程未指定 XML 目录时，XML 与 JSON 工程保存在同一目录；另存工程后随新目录保存。指定独立 XML 目录后，工程另存不会改变它。
- 导入 XML 会记住其来源目录。保存时文件名使用当前结构标识加 `.xml`；工程文件仍为 `.structure.json`。
- 目录和自动导出开关随工程保存。关闭开关可只保存 JSON。
- XML 导出失败时，已保存的 JSON 保留；界面明确提示错误，旧 XML 保持不变。
- 若目标 XML 含多个 Def，更新当前结构时保留其余定义。

墙体预览按材质选择光滑、木板或砖块连接图集，连续墙、拐角和实心墙块均按相邻对象连接；材质修改会即时刷新预览。

## 素材分类

搜索框下方依次为“集合、类型、分类、来源”，每项独占一行，可以组合使用；“重置筛选”恢复全部类型与来源。

| 集合 | 内容 |
| --- | --- |
| 全部素材 | 当前加载的所有来源 |
| 原版与 DLC | 仅基础游戏与 DLC，默认显示 |
| 玩家模组 | 只显示模组素材，来源栏按名称与 packageId 区分 |
| 常用 | 墙门、床桌椅、仓储、电力、温控、生产、常见地板和单位等常用对象 |
| 收藏 | 自己通过“☆ 收藏”或“对象 → 加入/取消收藏”管理的对象 |
| 最近使用 | 最近从素材库选用的对象，最近的在前 |
| 机械集群 | 保留 Wiki 的“杂项、控制器、炮塔”专题；额外模组条目会标注来源 |

建筑分类参考 [RimWorld Wiki 的建造菜单](https://rimworldwiki.com/wiki/Architect)：结构、生产、家具、电力、安保、温度、娱乐、艺术、杂项等，另外保留炮塔、储存、医疗、照明、收容、遗迹与废墟、自然岩石等常用细分类。单位有机械体、人类和动物；地形有人工地板、自然地表、水域、平台与桥梁等。分类顺序固定，默认列表先显示结构类。

## 启动与窗口缩放

游戏定义与首屏素材在后台读取，状态栏显示当前阶段；缩略图与画布贴图按需加载，加载时可正常移动、缩放窗口。预览加载完成后自动刷新，PNG 导出会等待所需贴图解码。

窗口支持每个显示器的 DPI 缩放，筛选行随侧栏宽度排列；初始窗口会限制在当前显示器工作区内。启动计时保存在 `%LOCALAPPDATA%/StructureEditor/startup.log`，用于定位特定素材来源的读取耗时。

输入文字和展开下拉菜单时，字母快捷键让位于输入操作。复制粘贴使用应用内部的对象剪贴板。粘贴预览时，Q 逆时针、E 顺时针各转 90°，左键落位，Esc 结束；R 仍可顺时针旋转。退出粘贴后，E 恢复擦除功能。

粘贴预览显示整组内容及项目数量，支持超过 128 项的布局，并随旋转、缩放和贴图加载同步刷新。绿色边框可放置，红色表示冲突；即使发生冲突，框内内容也保持可见。大组预览使用有内存上限的缓存，超出缓存范围时绘制视野内的对象。

放置笔刷和整组粘贴支持同类建筑覆盖：按相同建筑 DefName 判断，墙覆盖墙、路障覆盖路障，允许材质不同。新内容的材质、方向、休眠及框架修饰器生效；多格建筑只要被替换，就整体移除旧对象。整组先校验再覆盖，碰到不能覆盖的其他对象时不修改整组。地板保留在建筑下方；每次覆盖可一次撤销、重做。

右键在已有选择时删除所选整组；没有选择时删除鼠标下最上层可见对象。再次右键可删除下方地板。删除、整组移动、矩形铺设等可作为一次操作撤销。

## 初始状态

新从素材库放置的对象默认“初始唤醒”。**逐对象休眠暂为 MP 专用兼容**：在“导出”页使用 MechProtocol 格式，或在框架格式中勾选“启用 MP 扩展”，之后可对具有休眠能力的对象设置初态。多选可批量设置。双击吸取、复制和粘贴保留原对象的设置。

初始休眠只指定部署时的初态；受击、激活器、集群触发等后续行为由游戏和目标模组负责。无休眠组件的对象不能强加休眠。

## 保存、导出和备份

- `.structure.json`：完整可编辑工程，保存布局、材质、方向和对象初始状态。
- 框架 XML：主格式，由 Structure Framework 读取；支持建筑、单位、地形和对象扩展。
- 原版 PrefabDef：兼容原版定义格式，支持确定的建筑/地形布局；不支持的单位或扩展不会被偷偷删掉，而是阻止导出并说明原因。
- 独立结构内容包：创建 About.xml、布局 XML 和依赖清单，核心原版素材的内容包不依赖 MechProtocol。
- MechProtocol 兼容 XML：沿用该模组的 `MP_StructureDef` 数据契约；集群类别继续验证其五级命名规范。目标需安装相应模组。
- PNG：当前结构预览。

使用“保存位置”或“文件 → 工程保存目录”设置工程目录。导出文件的位置在导出对话框中独立选择。工程覆盖前会在 `%LOCALAPPDATA%/StructureEditor/Backups` 备份旧文件。

从 MechProtocol XML 导入后，请使用兼容导出更新游戏端 XML；Ctrl+S 保存的是独立工程。编辑器不自动替换任何协议启动集群。

## 游戏目录同步与框架 XML

在游戏中启用 Structure Framework，执行开发者工具 **Structure Framework → Export editor catalog**，再回编辑器按 **F5** 重新读取素材。编辑器会读取实际加载后的 Def（包含补丁与代码生成的建筑）；启用模组列表或加载顺序不匹配时退回 XML，不会套用旧目录。检索还可输入模组名称或 packageId。损坏的同步目录会完整回退，不混用已替换一半的数据。

可以导入框架显式坐标、共享调色板、符号布局和嵌套结构。当前桌面编辑器只编辑建筑、单位和地形；含屋顶层、命名标记或其他尚未建模的结构扩展时，会拒绝导入并说明，避免保存时丢失内容。原版 Prefab 的概率布局及未支持的额外字段也会拒绝导入。

## 当前支持范围

素材读取针对 RimWorld 1.7。支持 XML 继承、常见本地贴图、连接墙和炮塔顶层等预览；它不是游戏渲染引擎，不执行模组 C#、Harmony 或任意 XML PatchOperation。自定义着色器、特殊动态建筑、人物服装和部分运行时合成外观可能显示简化图或占位框。布局仍使用游戏的 DefName；缺失素材可保留在工程中，补齐来源后再导出。

本机设置位于 `%LOCALAPPDATA%/StructureEditor/settings.json`；错误和素材解析日志位于同一目录。不要把游戏贴图、DLL 或个人设置提交到项目仓库。


## 左侧结构库与阵地 PNG 预览

左侧「结构库」标签直接显示可展开的文件夹和结构名称；顶部工作栏的「结构库」按钮只切换左侧标签，不会另外弹出窗口。单击结构自动加载阵地 PNG 预览，双击或按 Enter 直接打开结构（不再需要点击文件后展开 DefName）。

项目自带的结构文件统一放在仓库根目录 `structures/`：同一 DefName 的 JSON 与 XML 在列表中合并为一项，优先打开 JSON 工程。预览优先读取同名 PNG 文件，没有时使用已加载的游戏贴图按当前结构生成 PNG 缓存。结构搜索仍会兼容其他已配置的目录。

### 重命名结构（同时追踪导出的 XML）

在左侧结构库对结构条目**右键 → 重命名…**，或选中条目按 **F2**。可分别修改显示名称（Label）和结构标识（DefName）。修改标识时，新 DefName 以 `MP_` 开头；若仅修改显示名称，原标识保持不变。

对话框会列出匹配到的关联 XML：包括与 JSON 同目录的 XML、工程记录的 `XmlExportDirectory` 下的 XML，以及结构库中按原 DefName 找到的 XML。确定后同步修改 JSON 和 XML 中的 `defName`、`label`，同名工程/XML/PNG 文件名也一起更新。若一个 XML 含多个结构定义，仅修改目标定义，保留其他定义和文件名。

重命名前会检测文件名及 DefName 冲突，避免覆盖其他工程；如果相关工程已有未保存的修改，需要先保存。所有被修改的原文件均备份到 `%LOCALAPPDATA%/StructureEditor/Backups/Rename_...`；失败时尝试恢复原件，成功后同步更新已打开的文档标签、最近文件记录和结构列表。已经导出到模组中的 XML 若未被软件识别为关联文件，仍需手动确认该输出目录。

软件会把「另存为 XML…」及其他已成功导出的具体 XML 路径记录在本机 `settings.json`（不会写进共享 JSON 工程），因此下一次重命名时也能识别非同名、非同目录的导出目标；旧版本尚未记录的自定义路径须重新导出一次才能建立关联。


## 界面与范围预览

- 顶部保留范围、保存和导出操作，应用图标放在原生深色窗口标题栏。
- 右上角「殉爆范围 / 探测范围 / 护盾范围」可分别开关。护盾读取射弹拦截组件与兼容护盾 Def 中公开的静态范围。
- Tab 循环切换编辑图层：全部 → 建筑 → 单位 → 地形；Shift+Tab 反向。文本框及下拉列表保留 Tab 导航；Ctrl+Tab 仍切换已打开文档。
- 某些 Mod 的护盾完全由运行时 C# 动态计算半径，未在 XML Def 中公布具体范围；编辑器不凭空显示半径。


### 标签关闭与范围快捷键

每个打开的工程标签右侧都有独立的 ×，点击可关闭对应结构。也可通过鼠标中键点击标签或使用 Ctrl+W 关闭当前工程。有未保存修改时，会使用原有的保存确认提示。

- Ctrl+G：切换殉爆范围。
- Ctrl+H：切换探测范围。
- Ctrl+J：切换护盾范围。
- Ctrl+D：复制所选对象并进入整组粘贴（原 Ctrl+J 功能已让位给护盾快捷键）。

素材库和属性侧栏使用统一深色标签页；左侧素材滚动条和下拉按钮采用协调的深蓝灰色，不再显示大块系统默认亮白区域。
